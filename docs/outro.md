## Digital Workers Need Disciplined Workflows

```text
Goal
  → Embabel GOAP planner selects an applicable typed action
  → Spring Bean reads a real system
  → Java runbook supplies domain context
  → model returns a domain object
  → bounded execution stops at the goal
```

The production advantage is **disciplined AI working through your existing Java system**.

---

## Everything Comes Together

| CAPABILITY | WORKING EXAMPLE |
|---|---|
| Multi-step orchestration | four-action SRE incident workflow |
| Bounded execution | Embabel `Budget` plus `FIRE_ONCE` actions |
| Tool coordination | type-driven action applicability |
| Java domain models | typed inputs, observations, assessments, reports |
| Spring Beans as actions | Docker, Redis, runbook, and model clients |
| GOAP and OODA | goal output plus observe/orient/decide/act actions |
| DICE | live state and runbook policy inside model context |
| JVM for production | compilation, tests, Redis, observability, Docker |

The worker can choose the path. **Your code still defines the world.**
